# Skill: Documentation Maintenance

## Obiettivo

Aggiornare sempre la documentazione insieme al codice.

## Regola

Ogni modifica che cambia struttura, flussi, endpoint, dipendenze, runtime o decisioni architetturali deve produrre un aggiornamento in `planning/docs/` o `planning/skills/`.

## Checklist

- stato progetto aggiornato se il progresso cambia
- documento tecnico corretto aggiornato
- nuove convenzioni documentate
- link e percorsi coerenti

## Da non fare

- rimandare la documentazione a fine fase
- creare file duplicati con contenuto sovrapposto
- lasciare file obsoleti senza allinearli
